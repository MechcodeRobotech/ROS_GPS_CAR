2 · ไอเอ็มยู / IMU BNO085 · มาตรวัดความเร่ง ไจโร และแม่เหล็ก

ปรับเทียบพร้อมกันทั้งสามอย่าง — มาตรวัดความเร่ง ไจโร และแม่เหล็ก — เพราะการเคลื่อนไหวชุดเดียวกันสอนได้ทั้งหมด ตัวเลข 0-3 ที่เห็นคือความมั่นใจ ของเซ็นเซอร์เอง · All three are calibrated together — accelerometer, gyroscope and magnetometer — because the same motion teaches all of them, and there is no reason to leave two of them stale. The 0-3 number is the sensor's own confidence, and the magnetometer is the slowest of the three to earn it, which is why it is the one still showing 0. This sensor calibrates itself from motion; the button only tells it to start learning again. Press Start, then move the robot in slow figure-of-eights — roll it, tip it, turn it — away from the motors and the battery, until the accuracy below reaches 2. Then press Save so it survives a power cycle.

หุ่นยนต์หาเครื่องนี้เจอได้อย่างไร / How the robot finds this PC

ใช้ mDNS ก่อน แล้วค่อย DNS · It tries three things in order and takes the first that answers.

  1. mDNS — mannaja.local. No router setup, no DNS server; the PC answers for its own name. This is the one that works here. Checking it by hand is a trap: plain avahi-resolve -n mannaja.local prints an IPv6 address and looks broken. The firmware asks for an IPv4 A record, so use avahi-resolve -4 -n mannaja.local.
  2. DNS — a plain lookup of the same name. Only works if your router registers DHCP client names, which many do not.
  3. Fixed address — AGENT_IP in the firmware. Last resort, and it goes stale on its own: it is a DHCP lease, so it changes. It had already drifted once here, pointing at an address nobody answered.

The board publishes itself as esp32-gps-localize.local, which is also how wireless firmware updates find it.

เชื่อมต่อไม่ได้ / When it will not connect

อาการ / Symptomสาเหตุที่พบบ่อย / Usual cause
Page will not load on the phone Phone is on a different Wi-Fi, or on mobile data. Both devices must be on the same network — mDNS does not cross networks.
gps-robot-web.local does not resolve Android below 12 has no mDNS support in the browser. Use the IP address shown above. iOS, macOS, Windows 10+ and Linux all resolve it.
Page loads but every value is stale The PC changed network after the stack started. DDS binds its interfaces at start-up, so the nodes keep advertising the old address: systemctl restart gps_localize.
ros2 or rqt shows nothing ROS_DOMAIN_ID must be exported, not just assigned. Without export the shell sees it and nothing it launches does, so every tool starts on domain 0 and shows an empty graph.
Robot is connected but will not move Check the stop reasons on the dashboard. With the mushroom pressed the contactor is open and the motors have no power at all.
